## Lagunas del ADR y decisión reversible

No se halló laguna de **núcleo** en J15: §11 y A2 ya fijan valores, error, orden, cierre y primario R; D15 §2.2 resuelve `Main()->I64`. Hay una laguna **local de trazabilidad de andamiaje**: la fila J15 dice «entradas variables» y §11 muestra un JSON, pero no dice allí explícitamente que J15 hereda **solo** el transporte `--mock-env` de A2 §12.4. No autoriza crear argv de aplicación ni stdin; se propone la siguiente adición exacta después del JSON de éxito de F0-0003 §11. **Decisión del coordinador, reversible tras revisión de B**, sin cambiar A2:

> En J15, «entradas variables» significa cambiar entre invocaciones el archivo JSON pasado a `nexo run` mediante `--mock-env`, conforme a A2 §12.4. `mock_request` entrega el límite y `mock_write_i64` entrega las respuestas en orden FIFO. No hay argumento posicional de aplicación ni lectura de stdin en este perfil. Ejemplo válido: guardar la fuente literal anterior como `ex04.n` y su entorno como `limite3.json`, y ejecutar `nexo run ex04.n --mock-env limite3.json --profile f0-0003-b-v1 --format json`; el resultado es `ok`, stdout `["0","1","4"]` y los eventos de la fila Completo. Ejemplo inválido de configuración: guardar `{bad` como `mala.json` y ejecutar el mismo comando con `--mock-env mala.json`; termina con exit 2, `outcome={"kind":"driver_error","reason":"invalid_mock_json"}`, `diagnostics=[]`, sin observaciones. Omitir `--mock-env` equivale a colas vacías y en esta fuente da `Err(-9000)` por `MockRequest`, sin adquirir recurso.

Si B considera redundante esa aclaración, S1 omite exclusivamente la edición documental: no se crea una regla nueva ni se fija en tests una laguna `adr_gap_*`. En particular, la fila `NB-J14-RUN-MAIN` de Pending.md no justifica cambiar la firma de entrada; el repro medido `fn Main()->I64{return 1;}` dio `check` exit 0 y `run` NX-E0112/invalid_main_signature `[3,7)`, que es exactamente la distinción de D15 §2.2.
