## Decisiones y mecanismo único

Separar temporales de `drive` mediante funciones locales con `#[inline(never)]`. `drive` conserva el único bucle y `Vec<Frame>`; `resume_non_match` permanece **sin extraer**: su reducción de 8.992 B en la copia no movió ninguna sonda 65 KiB (tabla anterior). `Frame` y `Task` siguen locales. Las firmas siguientes usan `<'a>` explícito para que el hijo y el `Frame<'a>` procedan de la misma expresión; `Checker<'_>` es independiente de ese préstamo. Firmas tipables en S4 (los cuerpos `todo!()` son marcadores del esquema; el prototipo llevó los cuerpos reales):

```rust

enum Resume { Next(Result<Type, Box<Diagnostic>>, FactId), Evaluate(FactId) }
fn enter_assignment<'a>(checker: &mut Checker<'_>, statement: &'a Statement, visit: FactId) -> Entry<'a> { todo!() }
fn enter_neg_not<'a>(expr: &'a Expr, context: OwnedCheckContext, expected: Type, visit: FactId) -> Entry<'a> { todo!() }
fn enter_binary<'a>(checker: &mut Checker<'_>, visit: FactId, expr: &'a Expr, context: OwnedCheckContext) -> Entry<'a> { todo!() }
fn for_range_error(checker: &Checker<'_>, statement: &Statement) -> Option<Box<Diagnostic>> { todo!() }
fn index_range_error(checker: &Checker<'_>, expr: &Expr) -> Option<Box<Diagnostic>> { todo!() }
fn binary_range_error(checker: &Checker<'_>, expr: &Expr) -> Option<Box<Diagnostic>> { todo!() }
fn resume_statement_match<'a>(checker: &mut Checker<'_>, visit: FactId, frame: Frame<'a>, result: Result<Type, Box<Diagnostic>>, frames: &mut Vec<Frame<'a>>, inner: &mut &'a Expr, inner_context: &mut OwnedCheckContext, pending_task: &mut Option<Task<'a>>) -> Resume { todo!() }
fn resume_expression_match<'a>(checker: &mut Checker<'_>, visit: FactId, frame: Frame<'a>, result: Result<Type, Box<Diagnostic>>, frames: &mut Vec<Frame<'a>>, inner: &mut &'a Expr, inner_context: &mut OwnedCheckContext, pending_task: &mut Option<Task<'a>>) -> Resume { todo!() }
```

`Entry` **solo desciende**: errores de rango se calculan antes, por referencia, y ponen `ready_result` sin mover `inner_context`. El ayudante crea el `Frame`, devuelve hijo y `FactId`; el despachador los instala una vez, sin reconstruir el hijo/hecho. `Resume::Next(result, visit)` devuelve ambos; `Evaluate(visit)` reanuda el único bucle. `inner_context` viejo se mueve entero al `Frame` de `enter_neg_not`/`enter_binary` y el nuevo contexto hijo sale en `Entry`. En `resume_expression_match`, el contexto poseído sale del `Box` dentro del ayudante y, al bajar por un brazo, se escribe una sola vez mediante `*inner_context`; no se desreferencia un `Box` de progreso en el marco de `drive`. El `Box<MatchProgress>` se mueve **como Box** al ayudante; se desreferencia allí solo cuando sea necesario. Esto evita un temporal de ≥168 B en `drive`, confirmado por su prólogo de 27.664 B en el prototipo, frente a 35.264 B en S4. Sin cierres capturantes, `Box<dyn>`, `thread_local`, hilos, recursión por profundidad de tipo ni segundo evaluador.
